# User Research Findings

## Overview

User research was conducted with 2 participants from another team in order to understand their expectations, needs, and frustrations when using a complaint management system.

---

## User 1

* Has previously used complaint platforms (e.g., customer service websites)
* Main issue: did not receive a response or response was very late
* Felt that complaint systems are not trustworthy
* Wants a **fast response** from the organization
* Wants to clearly see the **status of the complaint** (e.g., pending, in progress, resolved)
* Prefers a **simple and quick complaint submission process**
* Thinks attaching images or documents is useful for explaining issues
* Prefers using the system on **mobile devices**

---

## User 2

* Has rarely used formal complaint systems
* Usually avoids complaining because the process seems complicated
* Biggest concern: **too many steps and confusing interfaces**
* Wants a **very simple interface**
* Would use the system if it is **easy and fast**
* Wants to receive **notifications or updates** about complaint status
* Finds it important that the complaint reaches the **right authority**
* Prefers a clean and minimal design

---

## Key Insights

From the interviews, the following common needs were identified:

* Users want **fast and reliable responses**
* Users need **transparency** in complaint status tracking
* Users prefer **simple and user-friendly interfaces**
* Users value the ability to **attach files (images/documents)**
* Users want to be sure that their complaint is **handled by the correct organization**
* Users may prefer **mobile-friendly usage**

---

## Design Implications

Based on the findings, the system should:

* Provide clear **status tracking** for each complaint
* Offer a **simple and minimal UI**
* Allow **file uploads** during complaint submission
* Ensure complaints are routed to the **correct organization**
* Include optional **notifications or updates**
* Be **responsive** for mobile usage
